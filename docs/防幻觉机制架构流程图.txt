StarLearn 防幻觉机制 — 证据融合版架构流程图（v2.0 最优方案）
================================================================

设计原则（与 2026-08-20 统一设计一致）：
  1. 六项防护能力全保留，实现方式改为「数据驱动 + 条件触发」
  2. 证据融合取代层级堆叠：缺席证据剔除后权重重归一化，不设默认值
  3. 贵的操作（LLM 二次校验）只在置信度边界带触发（预期 ≤15% 请求）
  4. 已删除项：token logprobs（流畅度≠正确性）、常驻 Self-Check（延迟翻倍）、
     静态 regex 公式库（→向量数据 kb_facts）、"是/不是"共现冲突检测（必误报）

二、Reject 场景示例

用户提问: "证明1+1=3"
    │
    ▼ L0 PASS → RiskRouter: 数值运算 → VERIFY 模式
    ▼ LLM 生成（缓冲，不推送）
    ▼ 并行校验:
       L1  声明 "1+1=3" → KB 检索无出处 → claim_coverage 低
       F   kb_facts 未命中（非物理常数/历史事件）→ 不产证据
       L2  无 Web 结果 → 不产证据
       L3  无代码 → 不产证据
    ▼ 证据融合: citation 缺席, claim≈0.2, rag 底噪 0.4
       → confidence ≈ (0.2×0.25 + 0.4×0.15) / (0.25+0.15) ≈ 0.28
       → 落入 REJECT（<0.50），不触发 Self-Check（远离边界带）
    ▼ VERIFY 模式输出修正版:
       "抱歉，我对这个问题的答案不够确定…
        📚 正确内容: 1+1 = 2
        💡 建议: 查看教材第一章"

三、数据结构流转

TutorEvent
    ▼
RichContext（六路并行聚合: RAG/Web/记忆RRF/学习状态/SM2/截止日期）
    ▼
LLM 流式输出（STREAM 直推 / VERIFY 缓冲）
    ▼
GuardReport
    ├── decision: "accept" | "degrade" | "reject"
    ├── final_confidence: float
    ├── layers: [LayerResult(name, passed, score, reason, evidence)]
    ├── citations: [Citation(source_id, validated)]
    ├── corrections: [str]        ← F 层提供的正确内容
    └── self_check: Optional[{claims, verdict, adjustment}]
    ▼
ResponseEnvelope（answer/citations/confidence_report/links/actions）

四、延迟预算

  L0 + RiskRouter           < 2ms    纯 CPU
  L1 + F + L2 并行           ~50ms   向量查询 + 字符串处理
  L3 沙箱                    仅含代码时，≤5s 上限
  证据融合                    < 1ms
  Self-Check                 +0.8~1.5s，仅 ~15% 请求
  ─────────────────────────────────
  P50 附加开销               ~50ms   STREAM 模式下校验在流尾并发完成

五、灰度与验收

  feature_flags: GUARD_V2_MODE = off | shadow | enforce
