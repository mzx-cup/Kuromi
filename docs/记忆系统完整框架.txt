星识平台 · 记忆系统最优框架（v2.0）
====================================

一、学生的感受（目标不变）

学生小明今天登录平台，发现 AI 老师开口就说：
「小明，上次我们聊到一元二次方程的配方法，你当时卡在什么时候提取公因式。
今天我们从那一步继续，先看看你掌握得怎么样了。」
—— 这不是预设的台词，而是从记忆里实时召回的。

二、技术上完整实现后的样子

2.1 记忆分层运作

学生发消息
    │
    ▼
┌──────────────────────────────────────────┐
│ L1 · Working Memory（当前会话窗口）          │
│  系统指令 + 当前对话 + 本次召回的记忆片段    │
│  page_out: token 估算超阈值 → 旧轮次廉价模型 │
│  摘要 → 存 episodic + 嵌入 → 从 prompt 移除 │
└──────────────┬───────────────────────────┘
               │ 会话结束 / 轮次阈值
               ▼
┌──────────────────────────────────────────┐
│ L2 · Long-term Memory（三存储分工）          │
│                                          │
│  向量库（Qdrant，复用现有实例）              │
│  · mem_semantic: 语义记忆/对话摘要          │
│  · kb: 教材内容（真实 embedding 重嵌入）     │
│  · kb_facts: K12 事实条目（防幻觉 F 层数据） │
│                                          │
│  结构化存储（SQLite）                       │
│  · episodic / semantic 记忆表（已有）        │
│  · knowledge_node 邻接表（前置/强化关系）    │
│  · 4维评分 / 画像快照 / 偏好配置             │
│  · memories 全文索引（FTS5 + jieba 分词）   │
└──────────────┬───────────────────────────┘
               │ 需要时召回（page_in）
               ▼
         学生看到 AI 的回答

  与旧版愿景的区别：不引入 Chroma（Qdrant 已存在）、
  不引入 Neo4j（K12 规模邻接表足够）——零新增基础设施。

2.2 召回是双路并行的

任何一次召回请求（比如「小明现在该学什么」），系统同时做两件事：

  向量检索：Qdrant 语义 top-20（真实 embedding，非哈希伪向量）
  关键词检索：SQLite FTS5 + jieba top-20

两个结果用 RRF 公式融合排序（k=60），再按
confidence / access_count / confirmed 加权重排，取 top-k 拼入 Prompt。

2.3 真实 Embedding（地基，三级降级）

  主选: bge-small-zh-v1.5 本地推理（CPU ~10-50ms/条，免费离线）
  备选: MiniMax embedding API（网络依赖 ~100ms）
  保底: hash_embed（现有实现，链路不中断）

  现有 kb collection 内为 SHA-256 哈希伪向量（无语义），
  新建 collection 后台重嵌入，双 collection 过渡，不停服。

2.4 巩固与上下文调度（MemGPT-lite，复用现有管线）

  写路径: 对话结束/轮次阈值 → llm_extractor（已有）→ episodic（已有）
          → scheduler 定期 consolidation（已有）→ semantic 记忆
          → 嵌入入 Qdrant mem_semantic
  不引入完整 MemGPT 框架，扩展现有巩固管线。

2.5 每类记忆有最优存储位置

记忆内容            存在哪                          为什么
对话摘要            Qdrant mem_semantic            需要语义检索
知识点关系          SQLite knowledge_node 邻接表   规模小，图数据库不需要
K12 事实条目        Qdrant kb_facts + SQLite 源表  防幻觉 F 层向量命中
4维评分结果          SQLite                        结构化查询，教师报表
学生画像快照        SQLite + 图谱节点              查询用 SQLite，推理用邻接
Agent 工具定义      代码层                         永远不改
System Prompt       代码层                         永远不改

三、对平台各 Agent 的改变（不变）

Agent                  之前                之后
SocraticEvaluatorAgent 每次重新理解学生    提问前自动召回历史相似会话
ProfilerAgent          每次从零分析        分析结果写入图谱，下次直接加载
PlannerAgent           每次独立生成计划    参考学生的历史学习路径和偏好
EvaluationAgent        只看当前答案        参考学生在该知识点上的历史错误模式
TeacherPipeline        长对话越说越健忘    自动压缩旧内容 + 按需召回记忆

全部 Agent 走统一 MemoryRetriever v2 API（向量+FTS5+RRF），
一处优化全局受益。

四、和现有系统的区别

维度          改造前                        改造后（本方案）
跨会话记忆    只存结构化状态（SQLite）      结构化 + 向量双存储（Qdrant+SQLite）
语义检索      无（hash 伪向量/字符重叠）    真实 embedding 语义检索
关键词检索    200条全量扫+单字重叠          FTS5 + jieba 分词
融合排序      无                            RRF(k=60) + 业务重排
知识点推理    表存在，未用                  邻接表 BFS 前置关系推理
上下文管理    固定窗口                      超阈值摘要压缩（page_out）
多 Agent 共享 各 Agent 独立                统一 MemoryRetriever v2 API
