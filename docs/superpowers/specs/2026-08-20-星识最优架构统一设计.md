# 星识最优架构统一设计 v2.0

> **日期**: 2026-08-20
> **输入**: docs/防幻觉机制架构流程图.txt（6层v2愿景）、docs/记忆系统完整框架.txt（三层记忆愿景）、docs/消息链路.txt（现状）
> **目标**: 功能最强 + 性能最好。原三份方案的全部功能能力保留，实现方式与基础设施全部重选。
> **现状基线**: 防幻觉四层已实现（v1，非流式+伪流）、记忆=SQLite全量扫+字符重叠、KB=Qdrant+SHA-256伪向量、JailbreakDetector/巩固管线/knowledge_node/feature_flags/trace 均已存在。

---

## 0. 设计原则

1. **功能不缩水**：原 6 层防幻觉的每项能力都有对应实现，但从"静态规则 + 常驻重复调用"改为"数据驱动 + 条件触发"。
2. **流式不牺牲**：真流式贯穿全程，校验并发执行，修正用事件后补（correction 事件），不做"整段生成完再发"。
3. **证据融合取代层级堆叠**：每项校验产出"证据"；缺席的证据剔除后权重重归一化（修复 v1 默认 0.5、v2 固定权重堆叠两处缺陷）。
4. **贵的操作条件触发**：LLM 二次校验只在置信度边界带触发；K12 静态知识库改为向量检索的数据。
5. **零新增基础设施**：复用 Qdrant / SQLite / 现有 trace / feature_flags。不引入 Chroma、Neo4j。

## 1. 总体架构

```
用户消息
   │
   ▼
┌──────────────────────────────────────────────┐
│ L0 输入防护 (纯CPU <1ms)                       │
│ 越狱(已有JailbreakDetector) + 注入 + 超范围 + 敏感│
│ BLOCK → 直接返回友好提示, 记录trace             │
└──────────────┬───────────────────────────────┘
               ▼ PASS
┌──────────────────────────────────────────────┐
│ 风险路由 RiskRouter (纯规则 <1ms)               │
│ 高风险(公式/数值/考试/事实题) → VERIFY 模式      │
│ 普通对话/情感陪伴 → STREAM 模式                 │
│ (误判代价不对称: 误入VERIFY只损失流畅性→规则偏保守)│
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ ContextAggregator 并行聚合 (已有骨架, 升级召回)  │
│ ┌────────┐┌────────┐┌────────┐┌────────┐     │
│ │RAG向量  ││Web搜索 ││记忆双路 ││学习状态│ 并行 │
│ │检索    ││(条件)  ││RRF召回 ││SM2/DDL│      │
│ └────────┘└────────┘└────────┘└────────┘     │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ LLM 流式生成 (真流式, MiniMax-Text-01)          │
│   STREAM模式: 边生成边推送 text_delta            │
│   VERIFY模式: 缓冲完整回答                      │
│   [并发] LinkRecommender / ProactiveAdvisor    │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ 防护校验 (全并行 gather)                        │
│ L1 引用+声明锚定   L2 数值一致性                 │
│ L3 代码沙箱(已有)  F  K12事实库核验(吸收原L5)    │
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ 证据融合决策 (纯计算 <1ms)                       │
│ confidence = Σ(证据分 × 动态权重) / Σ权重        │
│ 边界带 [0.55, 0.75) → 条件触发 Self-Check       │
│ (小模型, 只验证 Top-2 风险声明, 预期≤15%触发)     │
├──────────────────────────────────────────────┤
│ ACCEPT ≥0.75 │ DEGRADE [0.50,0.75) │ REJECT <0.50│
└──────────────┬───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│ SSE 输出                                       │
│ text_delta / link / action / citation (已有)   │
│ correction (新增: 后补警示/修正卡片)             │
│ done (携带完整 GuardReport + confidence)        │
└──────────────────────────────────────────────┘
```

## 2. 方案A：消息链路（双模流式）

### 2.1 双模流式（核心创新）

| 模式 | 触发 | 行为 | 决策处理 |
|---|---|---|---|
| **STREAM** | 普通对话、情感陪伴 | token 生成即推送；校验在流结束后对完整文本并发执行（~50-150ms） | ACCEPT 无感知；DEGRADE 追加 `correction` 事件渲染免责卡片；REJECT 发高严重度 `correction`，前端折叠原答案（可展开），展示正确内容 |
| **VERIFY** | 公式/数值/考试/事实题 | 缓冲完整回答 → 校验 → 通过才推送 | 不通过直接输出修正版（拒答+正确内容+建议），**错误内容零曝光** |

RiskRouter 纯规则判定：公式特征（`=`、`^`、数学词）、数值运算、考试关键词、知识图谱节点命中 → VERIFY。规则偏保守（多 VERIFY 不伤正确性）。

### 2.2 并发编排

- ContextAggregator 六路并行（已有，保留）
- LinkRecommender / ProactiveAdvisor 与 LLM 生成**并发**（只依赖 rich_context，不依赖 answer）
- 防护层 L1/L2/L3/F 全并行 `asyncio.gather`，取 max 而非 sum
- SSE 事件向后兼容，仅新增 `correction`

## 3. 方案B：防幻觉 v2（证据融合版）

### 3.1 L0 InputGuard（新增打包，全 CPU）
- 复用已有 `JailbreakDetector`（engine.py 已接入，阈值 0.7）
- 新增：prompt-injection 正则（5 条）、out-of-scope 正则（4 条）、敏感词表
- BLOCK 短路返回，写入 trace

### 3.2 L1 GroundednessGuard（增强）
- 保留：`[Ref: xxx]` 引用校验（现有实现正确）
- 新增：关键声明提取（数值+单位 / 年份 / 定义句，正则）→ **声明锚定**：声明文本查 Qdrant KB 向量检索，相似度 ≥0.75 视为"有出处"
- 产出证据：`citation_score`、`claim_coverage`（锚定成功声明占比）

### 3.3 F：K12 事实核验（吸收原 L5，数据化）
原静态 regex 公式库 → Qdrant `kb_facts` collection 的**结构化数据条目**：

```json
{"name": "光速", "values": ["299792458", "3×10^8", "3e8"],
 "unit": "m/s", "tolerance": 0.01, "aliases": ["光速c", "真空中光速"],
 "category": "物理常数", "severity": "high"}
```

- 流程：提取回答中数值声明 → 向量检索命中事实条目 → 数值解析 + 容差比较（3×10^8 与 2.998×10^8 同条目别名，消灭 v2 的误报源）
- 优势：覆盖面靠**数据录入**扩展（运营维护 JSON 即可，不改代码）；容差/别名/严重度都在数据里
- REJECT 收紧：仅 high-severity violation 且命中置信度高才可触发 REJECT，否则只降分 + correction

### 3.4 L2 ExternalSourceGuard（修正）
- 保留：数值/版本号一致性检查（廉价有效）
- **砍掉**："是/不是共现 → 冲突"（长中文回答必误报）
- 替换：仅对 L1 提取的**声明对**做同主语矛盾谓词检查；无声明对则跳过

### 3.5 L3 CodeExecutionGuard（保留）
现有沙箱 + 竞赛模式短路（`STARLEARN_COMPETITION`）+ timeout，原样保留。

### 3.6 L4 证据融合（替换 logprobs + KG + 常驻 Self-Check）

```python
signals = {}
if 有引用:     signals["citation"] = (citation_score,  w=0.30)
if 有声明:     signals["claim"]    = (coverage,        w=0.25)
if 有web结果:  signals["web"]      = (consistency,     w=0.15)
if 事实命中:   signals["fact"]     = (match_rate,      w=0.20)
if 有代码:     signals["code"]     = (1.0 if pass,     w=0.10)
if 有RAG:      signals["rag"]      = (max_relevance,   w=0.15)  # 底噪信号
confidence = Σ(score·w) / Σ(w)   # 缺席信号剔除后归一化
```

- **删除 token logprobs**：① MiniMax 支持性未实测验证；② logprob 度量语言确定性≠事实正确性（流畅编造时照样高）；③ `×1.5` 放大系数无校准依据。35% 权重给伪信号不可接受。
- **KG 冲突检测不设独立层**：知识图谱节点内容进 KB collection，作为 L1 声明锚定的数据源。
- **条件 Self-Check**：confidence ∈ [0.55, 0.75) 才触发；一次调用；prompt 只含 Top-2 风险声明（锚定分最低的两条）；输出 ≤64 token；结果 ±0.15。预期触发率 ≤15%（大多数回答明显高/低置信，无需二次确认）。

### 3.7 决策与输出

| 决策 | 阈值 | VERIFY 模式 | STREAM 模式 |
|---|---|---|---|
| ACCEPT | ≥0.75 | 推送原文 | 已流出，无操作 |
| DEGRADE | [0.50, 0.75) | 原文+免责声明 | `correction` 事件追加免责卡片 |
| REJECT | <0.50 或 high-severity 事实违规 | 输出修正版 | 高严重度 `correction`，前端折叠原答案+展示正确内容 |

GuardReport（每层 passed/score/evidence/reason）全量写入现有 span trace。

### 3.8 延迟预算

| 环节 | 耗时 | 说明 |
|---|---|---|
| L0 + RiskRouter | <2ms | 纯 CPU |
| L1 锚定 + F 事实核验 + L2（并行） | ~50ms | 向量查询 2 次 + 字符串处理 |
| L3 沙箱 | 仅含代码时，≤5s 上限 | 已有 timeout |
| 证据融合 | <1ms | 纯计算 |
| Self-Check | +0.8~1.5s，仅 ~15% 请求 | 边界带条件触发 |
| **P50 附加开销** | **~50ms** | STREAM 模式下用户已看到全部内容，校验在尾部并发完成 |

对比：v2 设计稿（全程 logprobs + 常驻 Self-Check）每条消息 +1 次完整 LLM 调用（2-5s），且丢失流式。

## 4. 方案C：记忆系统（三存储分工，零新基础设施）

### 4.1 存储选型

| 数据 | 存储 | 变化 |
|---|---|---|
| 对话摘要 / 语义记忆 | Qdrant `mem_semantic` collection | 新增 |
| 情景记忆 | SQLite（已有 episodic）+ 摘要入 Qdrant | 扩展 |
| 知识点依赖关系 | SQLite `knowledge_node`（已有）邻接表，BFS 查前置 | **不引入 Neo4j**（K12 规模几千节点，邻接表足够） |
| K12 事实库 | Qdrant `kb_facts` + SQLite 源表 | 新增 |
| 4维评分 / 画像 / 偏好 | SQLite（已有） | 不变 |

**砍掉**：Chroma（Qdrant 已存在，双向量库纯增运维）、Neo4j。

### 4.2 真实 Embedding（地基，收益最大）

- **主选**：`bge-small-zh-v1.5` 本地推理（CPU ~10-50ms/条，无网络依赖、免费、离线可用）
- **备选**：MiniMax embedding API（网络依赖 ~100ms，维度以官方文档为准）
- **保底降级**：现有 `hash_embed`（链路不中断）
- 现有 KB collection 内是哈希伪向量（无语义），**新建 collection 后台重嵌入**，双 collection 过渡，不停服

### 4.3 双路召回 + RRF（替换 200 条全量扫）

```
query → [Qdrant 向量 top20] ∥ [SQLite FTS5 + jieba top20]
      → RRF(k=60) 融合
      → rerank(confidence / access_count / confirmed 加权)
      → top-k
```

替换 `memory_retriever.py` 的"拉 200 条全量 + 中文按单字重叠"打分。目标 P95 < 30ms。

### 4.4 巩固与上下文调度（MemGPT-lite，复用现有管线）

- **写路径**：对话结束/轮次阈值 → `llm_extractor`（已有）→ episodic（已有）→ `scheduler` 定期 consolidation（已有）→ semantic 记忆 → 嵌入入 Qdrant
- **page_out**：会话 token 估算超阈值 → 旧轮次廉价模型摘要 → 存 episodic + 嵌入 → 从 prompt 移除原文
- **page_in**：ContextAggregator 双路召回（已有接入点，仅换检索实现）
- 不引入完整 MemGPT 框架

### 4.5 多 Agent 共享

memory cards（profile / socratic / echo，已有）全部走统一 MemoryRetriever v2 API，一处优化全局受益。

## 5. 灰度与验收

- feature_flags：`GUARD_V2_MODE = off | shadow | enforce`；`MEMORY_V2 = off | on`
- **shadow 模式**：新链路计算但不改变输出，记录新旧决策 divergence → 用真实流量量化 false-reject 后再 enforce
- **黄金集**（50 题离线可跑）：20 常规 / 15 事实风险 / 10 代码 / 5 越狱，输出 Fact Precision、False Reject Rate、延迟对比报告
- 指标进现有 trace + dashboard

### 验收指标

| 指标 | 目标 |
|---|---|
| STREAM 首字延迟 P50 | < 800ms（恢复真流式） |
| 防护附加开销 P50 | < 50ms（无代码时） |
| Self-Check 触发率 | ≤ 15% |
| False Reject Rate | < 3%（shadow 期实测达标才 enforce） |
| 记忆召回 P95 | < 30ms |
| RAG 语义命中（黄金集） | 对比 hash 向量基线显著提升 |

## 7. 原方案 → 最优方案变更清单

| 项 | 原方案 | 最优方案 | 理由 |
|---|---|---|---|
| token logprobs | L4，35% 权重 | **删除** | 流畅度≠正确性；API 支持未验证；×1.5 无校准依据 |
| Self-Check | 常驻，40% 权重 | 边界带 [0.55,0.75) 条件触发 | 省 ~85% 二次调用；触发时只验 Top-2 声明 |
| L5 静态 regex 库 | 独立层 | kb_facts 向量数据 + 容差比较 | 数据可运营维护；别名/容差消灭误报 |
| "是/不是"冲突检测 | L2 | 声明对矛盾检查 | 消灭常态误报 |
| 层级固定加权 0.15~0.25 | 综合决策 | 证据动态归一化 | 修复缺席信号默认值缺陷（v1 的 0.5 / v2 的固定堆叠） |
| 生成后校验、伪流式 | v1/v2 共有 | 双模真流式 + correction 事件 | 功能与体验兼得 |
| Chroma | 新增向量库 | 复用 Qdrant | 零新增基础设施 |
| Neo4j | 新增图数据库 | SQLite 邻接表 | K12 规模不需要，纯增运维 |
| SHA-256 伪向量 | 现状 | bge-small-zh 本地 | 语义检索从 0→1，整条记忆/RAG 叙事的地基 |
| 记忆 200 条全量扫 | 现状 | 向量 + FTS5 + RRF | P95 <30ms，中文语义召回 |
| MemGPT 完整框架 | 愿景 | 巩固管线扩展（已有 scheduler/consolidator） | 复用现有资产 |
