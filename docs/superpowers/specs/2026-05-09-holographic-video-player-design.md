# 全息视界本地视频播放器设计

## 背景

全息视界当前已有独立页面入口、播放器样式和基础交互，但页面仍偏“课程进度预览 + 外部 B 站跳转”。本次目标是把 Kuromi 项目根目录下新建的 `video/` 作为本地视频仓库，并把全息视界设计成一个接近 B 站观看体验、同时保留星识学习辅助能力的播放器模块。

## 目标

- 在 Kuromi 根目录新增 `video/`，作为本地视频文件放置位置。
- 全息视界默认呈现类似 B 站的播放页：左侧主播放器，右侧选集/视频列表，下方视频信息和互动区。
- 在 B 站式布局中融合 AI 伴学笔记：知识点摘要、时间戳笔记、重点问题、片段跳转。
- 播放器支持真实本地视频播放，而不是只模拟进度或打开外链。
- 保留当前星识视觉气质：全息、科技感、学习驾驶舱，但界面结构优先服务视频观看。

## 非目标

- 不在第一版实现真实弹幕后端、弹幕持久化或用户间同步。
- 不做视频上传管理后台；第一版由用户直接把视频文件放入 `video/`。
- 不实现自动扫描视频元数据或 AI 自动生成笔记；第一版使用前端清单或静态示例数据承接。
- 不替换 hub、课程页或其他模块的整体导航体系。

## 页面布局

采用“第一版 B 站式播放页 + 第三版 AI 伴学笔记”的混合方案。

主区域为两列布局：

- 左侧主舞台：16:9 本地 `<video>` 播放器，包含播放/暂停、进度条、时间、音量、倍速、清晰度占位、全屏。
- 右侧学习栏：顶部使用标签页切换 `选集` 和 `AI笔记`。
- 下方信息区：视频标题、简介、学习进度、继续学习按钮、收藏按钮、弹幕输入。

默认状态显示 `选集` 标签，符合 B 站观看习惯。用户切到 `AI笔记` 后，右栏展示当前视频的学习辅助内容，不抢占主播放器空间。

移动端布局变为单列：

- 播放器优先显示。
- 选集/AI 笔记移动到播放器下方。
- 弹幕输入和视频信息保持在选集前后，避免 controls 过度拥挤。

## 本地视频接入

新增项目根目录 `video/`，并在后端暴露静态访问路径：

- 本地文件位置：`video/<filename>`
- 浏览器访问路径：`/video/<filename>`

第一版使用一个前端视频清单，例如：

```js
[
  {
    id: "python-algorithm-03",
    title: "算法复杂度分析",
    src: "/video/python-algorithm-03.mp4",
    duration: "45:30",
    progress: 0.35
  }
]
```

如果清单指向的视频不存在或暂时没有可播放视频，页面显示空状态：

- 提示用户把 `.mp4`、`.webm` 或 `.mov` 放入 Kuromi 根目录的 `video/`。
- 播放器区域保持完整布局，但不误导用户以为正在播放。

## AI 伴学笔记

AI 笔记作为右侧学习栏的第二个标签页。

笔记结构：

- 本节摘要：用 2-4 行概括当前视频核心内容。
- 时间戳笔记：每条包含时间、标题、简短说明，点击后跳转到对应播放时间。
- 重点问题：列出适合自测或向 AI 提问的问题。
- 学习建议：根据当前视频给出下一步观看或练习提示。

第一版笔记使用静态数据绑定到视频清单。后续可以替换为真实 AI 生成或后端接口，不影响播放器主体结构。

## 播放器交互

播放器行为：

- 点击视频区域或播放按钮切换播放/暂停。
- 拖动或点击进度条跳转时间。
- 点击选集切换视频，并重置当前视频的 UI 状态。
- 点击 AI 笔记时间戳跳转到对应时间并聚焦播放器。
- 倍速按钮在 `1x`、`1.25x`、`1.5x`、`2x` 间循环。
- 全屏按钮调用浏览器 Fullscreen API。
- 播放进度可以先保存在 `localStorage`，用于“继续学习”。

弹幕输入第一版只做前端即时展示：

- 用户输入后，弹幕文本在播放器区域短暂飞过或显示在弹幕列表。
- 不做跨会话保存。
- 关闭或刷新后弹幕消失。

## 视觉原则

- 保留现有 `video-player.css` 的深色全息背景、青蓝高亮和面板质感。
- 主播放器区域应比学习栏更强，页面第一视觉必须是视频本身。
- 右侧面板信息密度接近 B 站选集栏，但使用星识风格的标签、进度和知识点标记。
- 控件尺寸稳定，避免播放/暂停、倍速、全屏等交互导致布局跳动。
- 移动端按钮和文字不能重叠；必要时隐藏次要控件。

## 文件影响

预计实现会涉及：

- `video/`：新增本地视频仓库目录，可放置占位说明文件。
- `main.py`：新增 `/video/{filename}` 或静态挂载，用于访问本地视频。
- `html/video-player.html`：重构页面结构为 B 站式播放器 + 学习栏标签页。
- `css/video-player.css`：调整布局、播放器控件、选集栏、AI 笔记、空状态和响应式样式。
- `js/video-player.js`：接入真实 `<video>` 元素、选集切换、进度、本地弹幕、AI 时间戳跳转。
- `tests/test_video_player_links.py` 或新增测试：覆盖本地视频路径、页面结构和关键交互钩子。

## 测试策略

- 单元/文本测试：确认页面包含本地视频仓库提示、`/video/` 源路径、选集标签、AI 笔记标签和播放器元素。
- 后端路由测试：确认本地视频静态路径配置存在。
- 浏览器验证：启动本地服务后打开 `/video-player.html`，确认页面可加载、布局不重叠、无明显控制台错误。
- 如果 `video/` 中没有真实视频，验证空状态可读且不会破坏播放器布局。

## 验收标准

- 从 hub 进入全息视界后，看到的是完整播放器页，而不是外链推荐卡为主的页面。
- 页面明确使用 Kuromi 根目录 `video/` 作为本地视频来源。
- 主播放器支持真实 `<video>` 元素播放本地视频。
- 右侧可以在 `选集` 和 `AI笔记` 之间切换。
- AI 笔记时间戳能跳转播放器时间。
- 页面在桌面和移动端都没有明显文字溢出或控件重叠。
